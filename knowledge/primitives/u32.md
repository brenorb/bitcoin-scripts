# u32 word arithmetic

Represents a 32-bit word as four byte-valued stack items. The module provides
addition, subtraction, comparison, Boolean operations, shifts, rotations, and
stack manipulation. `u32_conditional_negate` adds normalized conditional sign
routing for a byte-word.

- **Position:** the main local byte-oriented backend for SHA-family and
  RIPEMD-family constructions.
- **Evidence:** `locally-reproduced`, including exhaustive byte-level logic tests.
- **Tradeoff:** operation fragments are moderate, while a reusable Boolean table
  occupies 256 stack items.
- **Representative results:** add is 78 bytes; subtract is 77; unsigned
  less-than is 38; conditional negate is 83; direct zero testing is 4.
  Canonical compressed-u32 decoding is 431 bytes with a 7-item peak; checked
  four-bit extraction is 73 bytes with a 5-item peak; canonical byte validation
  is 12 bytes with a 4-item peak. Little-endian bit conversion is 514 bytes
  with a 35-item peak. Conditional selection is 9 bytes with a 9-item peak
  and a 10–30-byte canonical nine-item witness.
- **Canonical compression question:** can a hostile four-byte word be
  compressed into the repository's signed u32 wire format while binding each
  input limb's raw encoding? The adapter reuses `u32_compress()` after four
  canonical-byte checks and measures 130 bytes with a 7-item peak.
- **Zero-test question:** can a u32 zero predicate avoid constructing a second
  zero word for `u32_equal()`? The local answer folds four per-limb zero tests
  with `OP_BOOLAND`, reducing the fragment from 21 bytes to 4 under the same
  compilation policy.
- **Zero-test boundary:** the four limbs are supplied in the existing u32
  representation; no hints are required, and callers must enforce canonical
  byte limbs when witnesses are hostile.
- **Consumers:** SHA-1, SHA-256, RIPEMD-160, and SHAKE256.

See the [implementation README](../../src/arithmetic/u32/README.md),
[technique page](../techniques/representations.md), and catalog record
`arithmetic/u32`.

The compressed-wire addition experiment is documented separately in
[compressed total-domain u32 addition](u32-compressed-add.md). It saves witness
width but is dominated for locking-script bytes by the ordinary byte-word
adder.

## Canonical byte-word compression

The research question is whether the existing byte-word compressor can be
used directly on hostile witness limbs without allowing raw ScriptNum aliases.
The hypothesis is that the existing `verify_canonical_byte()` boundary and a
temporary four-item alt-stack route are sufficient; the arithmetic compressor
itself remains unchanged. The comparison objective is the unchecked
`u32_compress()` fragment, which is 82 bytes locally, so the canonical adapter
adds 48 locking bytes for input binding.

The fragment consumes four minimally encoded byte limbs in the normal
most-significant-byte-first order and returns the same signed ScriptNum wire
value as `u32_compress()`: `0x80000000` maps to `-2^31`, and `u32::MAX` maps to
`-1`. It preserves unrelated main-stack and alt-stack items and uses no hints.
The threat model treats every limb as hostile; redundant sign bytes, negative
zero, negative values, and values above 255 fail before compression.

The measured boundary is fragment-only: four canonical-byte checks, temporary
routing, compression, and the output are included; witness pushes, output
checks, terminal predicates, unrelated live state, and transaction context are
excluded. Deterministic tests cover signed-domain boundaries, malformed
encodings at every limb position, and surrounding stack preservation. Evidence
is `locally-reproduced` under the strict local tapscript interpreter and the
execution class remains `unclassified`; no consensus or relay-policy claim is
made.
